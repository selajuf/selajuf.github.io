# Кирилл Головин — портфолио

Статический сайт на русском: шесть проектов, 10 изображений WebP, галерея, фильтры и страницы кейсов. Категории: агенты — 3, приложения — 2, видео и контент — 1. Публикационных MP4 нет. HTML, CSS и JavaScript без фреймворков, внешних сервисов и зависимостей. Шрифт Manrope хранится в репозитории вместе с лицензией OFL.

## Локальный запуск

Нужны Node.js 22+ и Python 3 для простого HTTP-сервера. Устанавливать пакеты не требуется.

```sh
npm run build
npm test
npm run serve
```

Откройте `http://127.0.0.1:4173/`. Остановить сервер: Ctrl+C. Можно использовать любой статический HTTP-сервер из корня репозитория.

Пока сервер запущен, в другом терминале выполните `npm run test:http`: проверка загрузит все страницы и используемые ресурсы, сверит HTTP-статусы, типы и содержимое с локальными файлами. `npm test` не требует сервера; он проверяет контент, ссылки, повторяемость сборки, синтаксис и логику фильтров и галереи. Эти проверки не заменяют просмотр в настоящем браузере.

## Структура

```text
content/projects.json      Проверенный контент и порядок кейсов
scripts/build.mjs          Генератор статических страниц
assets/site.css            Оформление и адаптация к экранам
assets/site.js             Фильтры и просмотр изображений
assets/fonts/              Manrope и лицензия OFL
cases/<slug>/index.html    Страница проекта
cases/<slug>/images/       Публикационные изображения WebP
tests/                    Автоматические проверки
index.html, 404.html       Главная и страница восстановления
robots.txt, sitemap.xml    Индексация
```

Готовые HTML-файлы лежат в корне и папках кейсов. Генератор обновляет только страницы, `robots.txt`, `sitemap.xml` и `.nojekyll`; контент и медиа не меняет. Результат сборки воспроизводим, без дат и случайных значений.

## Изменение материалов

Источник текста — `content/projects.json`. Не редактируйте сгенерированный HTML вручную. Главная начинается с заголовка «Работы» и фильтров без счетчиков; карточки содержат изображения, название и один абзац `summary`. Фильтры сохраняют категорию в URL, поддерживают прямые ссылки и Back; без JavaScript показаны все работы.

Поля `status`, `boundary`, `tags`, `shortTitle`, `flow`, а также `caption` и `kind` изображений сохраняются в проверенных данных, но не выводятся. Маркетингового intro, статусов, подписей изображений и повторного процесса в четырех шагах на страницах нет. Подход на главной и разбор задачи, входных данных, действий и результата в кейсах сохранены. Увеличение изображений сохраняет исходный `alt`, ссылку на оригинал, счетчик навигации, стрелки клавиатуры, Escape, блокировку прокрутки и возврат фокуса.

Чтобы заменить или добавить изображение, поместите публикационную копию WebP в `cases/<slug>/images/` и добавьте запись в `gallery`: `file` (путь от корня), `alt`, `caption`, `kind`. Генератор читает размеры WebP и добавляет их в HTML. Имена файлов: латинские строчные буквы, цифры, дефис или подчеркивание.

Чтобы добавить новый кейс после проверки его содержания, создайте папку `cases/<slug>/`, внесите проект в JSON по существующему образцу и осознанно обновите проверку количества и состава проектов в генераторе и тестах. `flow` содержит ровно четыре шага. Категории: `agents`, `apps`, `video`. Порядок на главной повторяет JSON. Затем выполните сборку и тесты.

## Публикация отдельно от сборки

Целевой адрес: `https://selajuf.github.io/`. Для GitHub Pages нужен пользовательский репозиторий `selajuf.github.io`; в Settings → Pages выберите Deploy from a branch, ветку `main` и папку `/ (root)`. Публикуется корень с готовыми HTML и `.nojekyll`; сборка на стороне Pages не нужна. Перед отправкой изменений запускайте команды выше. При смене домена обновите `origin` в генераторе и проверки канонических URL в тестах.

Сборка и тесты сами не создают коммитов, не отправляют данные и не публикуют сайт.
